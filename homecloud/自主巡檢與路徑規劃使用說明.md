# 自主巡檢與路徑規劃

目前先完成不需要車子的電腦模擬版本。它使用與未來實車相同的巡檢任務狀態機，但感測資料與移動結果來自模擬器，不會傳送馬達指令。

## 已完成功能

- 新增、刪除及編輯巡檢點名稱、X/Y 公尺座標、觀察時間與優先級。
- 依表格順序巡檢，或在同一優先級內安排較短路線。
- 使用占用格及 A* 規劃已知安全路線。
- 自動前往巡檢點，確認停車後才開始觀察倒數。
- 完成觀察後自動前往下一點。
- 前方新增障礙時更新地圖並重新規劃；沒有安全路線時停止。
- 定位逾時或可信度過低時立即停止並鎖定狀態。
- 支援暫停、恢復、取消、重設及完整事件紀錄。
- 模擬頁面清楚標示 `SIMULATION` 與 `hardware_commands_sent=0`。

## 啟動方式

只啟動巡檢模擬器：

```powershell
cd "C:\Users\lin40\Desktop\居家照護\homecloud"
python run_patrol.py
```

開啟：

```text
http://127.0.0.1:5004/patrol
```

若使用目前的照護監測服務，重新啟動 `run_homecare.py` 後也可以在同一個 port 開啟 `/patrol`。例如照護服務在 5003：

```text
http://127.0.0.1:5003/patrol
```

## 頁面測試順序

1. 保留預設四個巡檢點，選擇路線安排方式後按「開始巡檢」。
2. 觀察紅色機器狗沿藍綠色路徑移動，抵達後狀態應切換成 `observing`。
3. 按「模擬前方障礙」，應看到重規劃次數增加及路線改變；無安全路線時必須停止。
4. 按「模擬定位失敗」，目前指令必須變成 `stop`，狀態保持 `localization_lost`。
5. 按「恢復定位並繼續」，系統重新規劃後繼續任務。
6. 測試暫停、恢復及取消；暫停和取消期間指令必須維持 `stop`。

## 接實車前仍缺少的資料

巡檢控制器已將輸入統一為時間、位姿、定位可信度、前方距離及實測速度。實車接入時需要：

1. 經過地面校正的左右輪編碼器公尺數與實測輪距。
2. 有效且持續更新的前向距離資料；單一超音波只能做停止保護，無法確認轉彎兩側安全。
3. 由 SLAM 產生並確認來源的實測地圖，不能使用目前的 4×4 公尺模擬地圖。
4. 即時定位位姿及可信度，失去定位時必須停止。
5. Ranger 閘道健康檢查、控制板 watchdog、`DONE` 回覆和實體緊急停止測試。

完成上述項目後，模擬器提供的 `SensorSnapshot` 才能換成 Ranger 遙測來源，控制器輸出的 `forward/left/right/stop` 才能接到 `ranger_gateway.py`。目前沒有實車，因此這一段只能完成介面與安全條件，不能宣稱實體巡檢完成。

程式介面已放在 `navigation/ranger_patrol_adapter.py`。它會：

- 呼叫 Ranger 閘道的 `/health` 與 `/telemetry`。
- 使用 `navigation/calibration.json` 將左右輪 pulse 換算為公尺里程。
- 產生與模擬器相同格式的 `SensorSnapshot`。
- 傳送任務控制器產生的方向指令到 `/control`。
- 沒有明確開啟實車輸出時拒絕所有移動指令，但永遠允許傳送 `stop`。
- 每次啟用移動前重新檢查板名、序列埠、遙測新鮮度及前向距離。

目前尚未建立 `navigation/calibration.json`，Ranger 韌體的超音波也仍為停用，所以現況下實車前置檢查會拒絕自主移動。這是預期的安全結果。
