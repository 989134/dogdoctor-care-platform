# 室內建圖與巡檢原型

此版本先完成可測試的電腦端模組。現在實車只有方向回覆，沒有量測里程計，所以未啟用實車馬達，亦不能把模擬成果當成實車自主導航成果。

## 執行

在 homecloud 執行 `python run_navigation.py`，使用原專案 Python 環境。產出 `navigation/output/preview.html`、`map.json` 與 `result.json`。預設模擬 4×4 公尺房間與 360 度距離掃描，這不是 Ranger 已有感測能力。三個巡檢點寫在 `navigation/waypoints.json`，每筆為 `[x公尺,y公尺,停車觀察秒數]`。

目前完成：左右輪累積行程的差速里程計、帶未知區域的占用格地圖、局部掃描與地圖匹配、障礙膨脹、A*、抵達後確認速度接近零才開始計時、障礙或定位資料逾時即停止、暫停與恢復狀態。方向是建議值，未傳送至控制板。觀察狀態目前只計時，未自動控制攝影機或呼叫照護服務。

## 真實資料重播

`python run_navigation.py --replay 實測資料.jsonl`

每行 JSON 欄位：

- `t`：感測器同步後、單調遞增的秒數。
- `left_m`、`right_m`：左右輪有正負號的累積實測行程，公尺。不能用指令次數產生。
- `rays`：`[[方向弧度,距離公尺,是否命中障礙], ...]`，正角度朝左。必須是已校正的量測，感測器原點先轉到車體中心；無有效讀值應略過，不能當作無障礙。
- `front_m`：前向安全距離實測值，公尺。
- `speed_mps`：實測車速，公尺／秒。

重播不是即時控制，它不測通訊中斷、控制板 watchdog 或輪子實際執行能力。地圖以第一筆位姿為原點。輪距預設 0.18 公尺僅供模擬，實機必須換成實測／校正數值，履帶需要另考慮轉向打滑。載具不可超出已知地圖範圍。

## 尚需硬體資料與整合

1. 已加入候選 MeAuriga 韌體，會回傳左右輪累積 pulse、轉速、時間戳與啟動識別；尚待燒錄及架空車輪實測。地面公尺換算需用 `calibrate_encoder.py` 校正。
2. 距離量測須標記單位、方向、時間與無效狀態。單一前方超音波不足以提供示範中的完整掃描，也不能證明轉彎時兩側安全。
3. 已加入控制板端定時停止、看門狗、速度回授，以及樹莓派端 `DONE` 等待與逾時停止；尚待實機驗證。協定目前沒有指令序號，同時只允許一個移動交易，停止可優先插入。
4. 已加入獨立 `ranger_gateway.py`，不覆蓋目前已成功的控制程式。它必須取代舊服務成為 `/dev/ttyUSB0` 的唯一擁有者，不能兩個服務同時啟動。

## SLAM 與 Depth 的範圍

目前是輪式里程計＋局部占用地圖掃描校正，未完成全域閉環、重定位、多樓層或長時間漂移修正，不應稱為完整 SLAM。局部掃描匹配需要足夠的有效射線；資料不夠時沿用里程計並累積不確定度，超過門檻停止。

`depth_advisory()` 僅彙整 Depth Anything V2 的相對數值，明確標成非公尺，不能送入量測射線介面。下一階段需使用目前鏡頭的標定、已知距離參考與不同場景驗證尺度穩定性。此版本尚未用真實 Depth 資料證明定位改善；不會把相对深度直接加入公尺地圖。

## 驗證

`python -m unittest discover -s tests -q`。目前完整測試套件共 43 項通過，涵蓋照護偵測、導航、遙測解析、校正、`DONE` 等待、逾時停止與停止優先。預設三點模擬已到 complete。這些都是原型驗證，不代表實車可在長者周圍安全運作。
